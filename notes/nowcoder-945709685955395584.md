# 小鹏集团深度学习平台研发工程师面经

岗位背景：27 届校招，深度学习平台研发工程师。
面试形式：飞书视频面试，含在线代码考核。
考察方向：AI Infra 基建、分布式训练、云原生调度、大模型推理优化、图论算法。

候选人候选人复盘：平台研发岗位与纯算法岗位不同，重视底层原理、系统架构能力和工程落地经验。以下是面试中重点追问的方向。

## 一、分布式训练与 GPU 资源调度

1. DDP（Distributed Data Parallel）的底层机制。

考点：多卡训练是怎么同步梯度的？

候选人复盘：重点讲了 DDP 的多进程架构（无主卡概念）和 Ring All-Reduce 机制。面试官追问了“梯度分桶（Bucketing）与计算通信重叠”是怎么实现的，这里必须懂反向传播过程中如何隐藏通信延迟。

候选人提示：千万别把 DDP 和 DP（DataParallel）搞混，强调 DDP 绕开了 GIL 锁，且不节省单卡显存。若提梯度累积，要懂 no_sync()。

2. GPU 架构与 LLM 推理瓶颈。

考点：H100 和 B200 有什么区别？LLM 推理瓶颈在哪？

候选人复盘：要能清晰区分 Prefill（计算密集） 和 Decode（带宽密集） 两个阶段。对比了 Hopper 和 Blackwell，提到了双芯片封装带来的 HBM 带宽提升（8 TB/s），以及 Blackwell 原生支持 FP4 精度对吞吐量的质变（但要评估精度折损）。

3. K8s 中的 GPU 调度。

延伸考点：平台怎么管理异构算力？（涉及云原生）

## 二、云原生底座与虚拟化

4. K8s 的 Pod 内部创建与调度链路。

候选人复盘：从 kubectl 提交 YAML -> API Server 鉴权准入 -> etcd 存储 -> Scheduler 选节点 -> kubelet 调 CRI 起容器。面试官还问到 Pause 容器的作用（共享网络命名空间）。

5. K8s、KVM 和 KubeVirt 的关系。

考点：深度学习平台有时需要强隔离环境（比如跑特定的老旧框架），怎么让 K8s 管虚拟机？

候选人复盘：引出了 KubeVirt。核心逻辑是“VM inside Pod”，通过 CRD 扩展 K8s API，把 KVM 虚拟机包装在 Pod 里运行。还对比了 Kata Containers（让容器变得像 VM 提供强隔离）。

## 三、大模型接口与工程化

6. 流式（Stream）与非流式（Non-stream）的工程差异。

考点：平台对外提供推理服务，接口怎么设计？

候选人复盘：非流式返回一次性 JSON，流式基于 SSE（Server-Sent Events） 持续推送 delta.content。

候选人提示：流式下的 usage 字段默认隐藏，必须显式开启 stream_options；流式输出审核存在难点（Chunk 级别语义不完整，导致安全拦截失效，需要端到端的拼接校验）。

7. 平台合规与安全审计。

聊到了类似 OpenAI Moderation 的接口。如果平台做网关，输入输出过滤怎么做？顺带探讨了 Adversarial Prompt（对抗性提示词）如何通过编码/自重建绕过单纯的表层语义审查。

## 四、编程题（图论）

8. DAG（有向无环图）的拓扑排序。

场景：经典的平台调度算法题（节点依赖关系、任务执行顺序）。

解法：Kahn 算法（BFS）。

邻接表建图，统计每个节点的入度。入度为 0 的节点入队。出队并将邻居入度减 1，若变 0 则继续入队。防御性编程：如果最后遍历的节点数小于总节点数，说明有环，应返回或输出特定标志（视题目而定）。候选人教训：在线机考不能只写 System.out.println("hello world")，应使用 Scanner 读取和处理输入，否则测试用例无法通过。

## 五、候选人心得

1. 工程落地：平台研发极度看重“平台化思维”。你做的项目能不能抽象给全公司用？高可用、容灾、集群扩容你是怎么设计的？

2. 开源与实习相结合：车企大厂（小鹏）对基础架构的要求很高，极少硬卡学历或大厂背景，更看重综合匹配度。最高级的简历故事线：在开源社区（如 K8s / vLLM）发现问题 -> 技术论坛/博客沉淀思考 -> 在实际企业项目中落地验证。候选人认为这样的经历组合很有优势。

3. 坦诚面对知识盲区：面试官审美各异，有人喜欢造轮子的，有人喜欢干实事的。遇到不会的底层知识（比如具体的 CUDA 算子优化），大方承认并讲出你的排查思路，比编造答案更好。

候选人建议：飞书面试不要使用豆包 / 抖音账号登录，以免影响入职背调；提前调试电脑摄像头。
