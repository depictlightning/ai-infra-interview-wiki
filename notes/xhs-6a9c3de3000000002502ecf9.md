开场先是数据结构和网络原理热身：
	
链表、二叉树、哈希表的复杂度和使用场景；
几千到几万个定时器该如何管理，堆的插入、触发复杂度；
TCP / UDP 的区别、三次握手；
多台机器共用交换机时，TCP 和 UDP 在不同数据规模下的实际表现。
	
这部分让我很清醒：AI Infra 不会因为你做过 CUDA，就不问基础。尤其是计网、数据结构这些，得能真的顺着场景往下推，而不是只记几个结论。
	
项目部分主要深挖了四块：
TP + CUDA Graph 场景下的稳定性排查。 从大规模超时开始，先缩到 TP=2 的最小复现，再对比 TP=1 / TP>1，最后把范围收敛到一条融合通信路径的状态同步问题。面试官会继续问：Graph 是触发条件还是根因？通信双方怎么判断 buffer 状态？为什么默认路径没复现？
	
确定性 Router GEMM。 会问为什么 Split-K 会影响确定性、为什么固定配置的 persistent kernel 在小 M 下浪费严重，以及如何根据 shape 选更合适的路径，同时保留回退方案。
	
Decode 侧减少 CPU/GPU 同步等待的融合算子。 重点是原先的数据为什么要来回经过 CPU，哪些计算可以留在 GPU 上完成，怎样减少 decode 中反复出现的空隙。
	
NCCL 与推理系统设计。 Ring / Tree All-Reduce 怎么工作、各自偏吞吐还是延迟；如果做多节点 Prefill / Decode 分离，Prefill 产生的 KV Cache 怎么给 Decode 节点，通信方式和缓存复用该怎么权衡。
	
这场最大的收获是：以后讲项目不能只停在“我定位并修了一个 bug”。要能完整讲出：
触发条件 → 最小复现 → 排查假设 → 根因范围 → 修复边界 → 正确性与回归验证。
