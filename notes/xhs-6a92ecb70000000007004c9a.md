这场不算单纯的算子面。开头从项目切入，后面不断往推理框架、CUDA Graph、确定性计算、量化和 RL Infra 延伸，整体更像在验证：项目是不是自己做过，底层链路能不能讲清楚。
	
主要被问了这些：
	
MoE Router Replay 到底怎么接进 RL 流程。 不只问“为什么能降低推训不一致”，还会追 rollout 端的 Top-K 路由信息怎么记录、怎么随数据传给训练侧、CPU/GPU 之间如何搬运。
	
vLLM 的整体结构。 从请求进来，到 scheduler、engine、worker、model runner，再到下层算子和通信，数据流、控制流分别怎么走。
	
TP + CUDA Graph 的卡死问题。 会问怎么从大规模问题缩到 TP=1 / TP>1 的对比，为什么 Graph 只是触发条件，真正的问题可能出在被替换的融合通信路径；还会继续问 capture / replay 的约束，例如 kernel、shape、地址等哪些必须稳定。
	
确定性 Router GEMM。 为什么 Split-K 会导致结果不完全一致，固定配置为什么会在 Decode 的小 M 场景浪费资源，动态选配置和回退路径如何设计。
	
Decode 侧的融合算子、量化和模型结构。 包括 CPU/GPU 来回同步怎么减少、W4A16 / AWQ / QAT、MHA / GQA，以及 RL 框架本身的理解。
	
这场最直接的收获是：项目结果能讲，不代表项目就能扛住深挖。
	
后面我最该补的其实就三件事：
	
把 vLLM 从请求到 kernel 的全链路重新走一遍；
把 CUDA Graph 的捕获、显存和 replay 约束讲清楚；
把量化、Attention 和 Router GEMM 的收益拆开，不再把多个优化的总结果混成一个数字。
